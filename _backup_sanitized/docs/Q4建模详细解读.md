# Q4环境影响评估模型详细解读

## 引言：Q4建模的整体框架

Q4（环境影响评估）是MCM 2026 B题的最终评估模块，负责将前三问（Q1基线、Q2非完美工况、Q3水资源保障）的工程参数转化为环境指标。其核心任务是构建一个**多物理机制耦合的环境影响评估模型**，为太空基础设施决策提供科学依据。

### 建模哲学
1. **全生命周期视角**：从“摇篮到坟墓”评估环境代价
2. **漏桶动态模型**：追踪平流层黑碳的累积与衰减
3. **能源结构耦合**：考虑电网脱碳对未来项目的影响
4. **蒙特卡洛风险**：捕捉随机故障的环境后果

### 技术架构
- **输入层**：继承Q1-Q3的运输参数、可靠性参数、需求参数
- **仿真层**：离散事件仿真引擎（1天时间步长）
- **环境层**：黑碳漏桶模型 + CO₂核算 + LCA评估
- **评估层**：环境破坏指数（EDI）综合指标

### 1.4 关键共享变量

#### 1.4.1 α（电梯运输占比）
- **Q1定义**：`α = 电梯运量 / 总运量`，通过`alpha_star()`函数优化
- **Q4实际值**：`alpha_actual = mass_elev_ton / (mass_elev_ton + mass_rocket_ton)`
- **物理意义**：衡量运输结构的环境友好性。α越高，对平流层环境影响越小。

#### 1.4.2 火箭发射参数
- `K_pads`：发射场数量（1-10个），决定**最大并发发射能力**
- `r_rate`：每日发射率（1.0-3.0次/场·天），决定**持续发射强度**
- `q`：有效载荷（100-150吨/次），决定**单次运输效率**

#### 1.4.3 时间步长与仿真周期
- **统一时间步长**：1天（Q2、Q3、Q4保持一致）
- **仿真周期**：1825天（5年）或至完成100百万吨运输
- **随机种子**：可重复的蒙特卡洛仿真

### 1.5 数据流耦合架构

## 第二部分：Q4核心模型详细解析

Q4的核心创新在于构建了**环境账本（EnvLedger）**系统，将工程参数转化为生态指标。

### 2.1 环境账本（EnvLedger）类结构

```python
class EnvLedger:
    def __init__(self, cfg: EnvConfig):
        self.cfg = cfg
        self.attempts_total = 0.0          # 累计火箭发射次数
        self.attempts_by_year = defaultdict(float)  # 年度发射统计
        self.attempts_by_site = defaultdict(float)  # 发射场统计
        self.mass_elevator_total_ton = 0.0  # 累计电梯运量
        self.S_bc = 0.0                    # 当前黑碳库存
        self.S_bc_max = 0.0                # 峰值黑碳库存
        self.E_BC = 0.0                    # 累计黑碳排放
        self.history_S_bc = []             # 历史记录（用于绘图）
```

**设计理念**：环境账本像会计记账一样，逐日追踪**黑碳库存、CO₂排放、臭氧风险**等环境债务。

### 2.2 平流层黑碳"漏桶"模型（核心物理模型）

#### 2.2.1 微分方程
```
S(t+1) = (1 - δ) × S(t) + u(t)
```

#### 2.2.2 参数定义
| 符号 | 代码变量 | 物理意义 | 典型值 | 单位 | 科学依据 |
|------|----------|----------|--------|------|----------|
| S(t) | `self.S_bc` | 第t天平流层黑碳存量 | 动态 | 吨 | 核心状态变量 |
| u(t) | `n_attempts × e_BC_per_attempt_ton` | 日黑碳注入量 | 动态 | 吨/天 | 火箭发射函数 |
| δ | `1 / (tau_bc_years × 365)` | 日衰减率 | 1/(4×365)≈0.000685 | 1/天 | 平流层沉降 |
| τ | `tau_bc_years` | 黑碳半衰期 | 4.0 | 年 | IPCC AR6 评估 |

#### 2.2.3 代码实现（env_ledger.py:44-65）
```python
# 日黑碳排放
u_t = n_attempts * self.cfg.e_BC_per_attempt_ton  # e_BC_per_attempt_ton = 0.1吨/次

# 衰减率计算
delta = 1.0 / (self.cfg.tau_bc_years * 365.0)

# 存量更新（漏桶核心）
self.S_bc = (1.0 - delta) * self.S_bc + u_t

# 追踪峰值（环境风险指标）
if self.S_bc > self.S_bc_max:
    self.S_bc_max = self.S_bc
```

#### 2.2.4 物理机制解释
1. **"漏桶"比喻**：平流层像个缓慢漏水的桶，黑碳注入像加水，自然沉降像漏水
2. **时间尺度**：τ=4年意味着**黑碳影响持续数十年**，远长于项目工期
3. **非线性效应**：峰值库存`S_max`对辐射强迫有指数级影响

### 2.3 CO₂排放计算（温室气体核算）

#### 2.3.1 火箭直接排放
```
E_CO2_rocket_ton = attempts_total × e_CO2_per_attempt_ton
```
- `e_CO2_per_attempt_ton` = 2000.0 吨/次（基于重型火箭甲烷燃烧）

#### 2.3.2 电梯间接排放
```python
energy_elev_kwh = mass_elevator_total_ton × epsilon_E_kwh_per_ton
E_CO2_elev_ton = energy_elev_kwh × g_grid_kgco2_per_kwh × (1 - chi_green) / 1000.0
```

| 参数 | 代码变量 | 物理意义 | 典型值 | 单位 |
|------|----------|----------|--------|------|
| ε_E | `epsilon_E_kwh_per_ton` | 电梯能耗强度 | 15000.0 | 千瓦时/吨 |
| g_grid | `g_grid_kgco2_per_kwh` | 电网碳强度 | 0.2 | 千克CO₂/千瓦时 |
| χ | `chi_green` | 绿电比例 | 0.0-1.0 | 无量纲 |

#### 2.3.3 总CO₂排放
```
E_CO2_total_ton = E_CO2_rocket_ton + E_CO2_elev_ton
```

### 2.4 臭氧风险评估

#### 2.4.1 软约束惩罚（经济成本）
```python
E_O3_penalty = Σ max(0.0, 年度发射次数 - N_safe_year)
```
- `N_safe_year` = 1000 次/年（年度安全阈值）
- **物理意义**：超量发射的臭氧破坏"环境税"

#### 2.4.2 硬约束可行性（技术底线）
```python
feasible_o3 = all(年度发射次数 ≤ N_max_year)
```
- `N_max_year` = 5000 次/年（年度绝对上限）
- **工程意义**：超过此限可能导致臭氧层不可逆破坏

### 2.5 生命周期评估（LCA）计算

#### 2.5.1 电梯建设碳债
```python
E_LCA_build_ton = (m_tether_total_ton × 1000.0
                   × e_graphene_MJ_per_kg
                   × g_mfg_kgco2_per_MJ
                   / 1000.0)
```

| 参数 | 代码变量 | 物理意义 | 典型值 | 单位 |
|------|----------|----------|--------|------|
| m_tether | `m_tether_total_ton` | 缆索总质量 | 10000.0 | 吨 |
| e_graphene | `e_graphene_MJ_per_kg` | 石墨烯制造能耗 | 1000.0 | 兆焦/千克 |
| g_mfg | `g_mfg_kgco2_per_MJ` | 制造碳强度 | 0.05 | 千克CO₂/兆焦 |

#### 2.5.2 LCA物理意义
- **一次性债务**：电梯建设产生巨大"隐含碳"
- **分摊问题**：如果项目持续100年，年均碳债较低
- **材料创新**：石墨烯能耗远高于传统钢材

### 2.6 环境破坏指数（EDI）计算

Q4使用了**两种不同的EDI计算公式**，适应不同分析场景。

#### 2.6.1 简化EDI（用于参数扫描）
```python
# run_q4_env_sweep.py:145-146
edi = (env_metrics['E_CO2_ton'] / 1e6) + (env_metrics['S_max_ton'] / 10.0)
```

**公式解释**：
```
EDI_simple = (CO₂排放/1,000,000) + (峰值黑碳/10)
```

**设计逻辑**：
- CO₂项除以1,000,000：将百万吨级排放归一化到0-1区间
- 黑碳项除以10：将吨级黑碳归一化到0-1区间
- **简单加权**：隐含假设CO₂和黑碳影响权重相等

#### 2.6.2 标准化EDI（用于蒙特卡洛）
```python
# run_q4_detailed_sim.py:225-229
df['EDI_proxy'] = (
    (df['E_CO2_ton'] / df['E_CO2_ton'].mean()) +
    (df['S_max_ton'] / df['S_max_ton'].mean()) +
    (df['E_O3_penalty'] / (df['E_O3_penalty'].mean() + 1e-6))
) / 3.0
```

**公式解释**：
```
EDI_standard = 1/3 × [(CO₂/CO₂均值) + (S_max/S_max均值) + (O₃惩罚/O₃惩罚均值)]
```

**设计逻辑**：
- **均值归一化**：每个指标除以其在所有配置中的平均值
- **三项平均**：CO₂、黑碳、臭氧风险权重各1/3
- **加性模型**：假设环境破坏是三个维度损害的线性叠加

#### 2.6.3 EDI比较
| 特征 | 简化EDI | 标准化EDI |
|------|---------|-----------|
| **适用场景** | 参数扫描、快速评估 | 蒙特卡洛、详细分析 |
| **指标数量** | 2项（CO₂、黑碳） | 3项（CO₂、黑碳、臭氧） |
| **归一化方法** | 绝对阈值除法 | 相对均值除法 |
| **权重分配** | 隐含相等 | 明确相等（1/3） |
| **灵敏度** | 对绝对值敏感 | 对相对排名敏感 |

### 2.7 仿真引擎工作原理

#### 2.7.1 离散事件仿真流程
```python
def run_single_trace(K_pads, r_rate, chi_green, elev_scale):
    # 1. 初始化环境账本
    ledger = EnvLedger(env_config)

    # 2. 每日循环
    for day in range(T_total):
        # 2.1 计算当日火箭发射（复用Q3逻辑）
        attempts_today = calculate_rocket_attempts(K_pads, r_rate, preset)

        # 2.2 计算当日电梯运量（复用Q3逻辑）
        m_E = calculate_elevator_delivery(elev_scale, preset)

        # 2.3 更新环境账本（核心）
        ledger.step_day(day, attempts_today, m_E)

        # 2.4 检查完成条件
        mass_delivered += (m_E + m_R)
        if mass_delivered >= target_mass:
            break

    # 3. 计算最终环境指标
    env_metrics = ledger.finalize()
    return env_metrics
```

#### 2.7.2 蒙特卡洛随机性来源
1. **设备故障**：指数分布故障间隔（λ = (1-A_E)/A_E × μ）
2. **天气影响**：二项分布可用性（成功概率 = A_B）
3. **发射失败**：二项分布成功率（成功概率 = 1 - P_R）
4. **维修时间**：指数分布维修时长（均值 = MTTR_E_DAYS）

#### 2.7.3 参数扫描设计
| 扫描变量 | 符号 | 扫描范围 | 步长 | 物理意义 |
|----------|------|----------|------|----------|
| 电梯份额 | α | [0.0, 1.0] | 0.1 | 运输结构 |
| 脱碳率 | χ | [0.0, 1.0] | 0.01 | 能源清洁度 |
| 发射场数 | K | [1, 5, 10] | 离散 | 发射能力 |
| 发射率 | r | [1.0, 3.0] | 离散 | 发射强度 |
| 电梯规模 | elev_scale | [0.0, 0.4, 1.0] | 离散 | 电梯容量 |

**计算过程**：

**物理机制**：
- **锯齿状上升**：每次发射注入黑碳，随后缓慢衰减
- **衰减斜率**：由δ=1/(4×365)≈0.000685决定
- **稳态水平**：当注入率 = 衰减率时达到平衡

**核心发现**：

### 4.2 核心公式汇总

#### 4.2.1 漏桶模型公式
```
差分方程：S_{t+1} = (1 - δ)S_t + u_t
日衰减率：δ = 1 / (τ_{BC} × 365)
日注入量：u_t = n_attempts × e_BC_per_attempt_ton
```

**物理意义**：平流层黑碳像漏水的桶，每天有注入（发射）和漏出（沉降）。

#### 4.2.2 CO₂排放公式
```
火箭排放：E_CO2^{rocket} = N_attempts × e_CO2_per_attempt
电梯排放：E_CO2^{elev} = M_elev × ε_E × g_grid × (1-χ) / 1000
总排放：E_CO2^{total} = E_CO2^{rocket} + E_CO2^{elev}
```

**物理意义**：火箭是直接燃烧排放，电梯是间接电力排放（依赖电网清洁度）。

#### 4.2.3 臭氧风险公式
```
软约束：E_O3 = Σ_y max(0, N_y - N_safe)
硬约束：feasible = ∀y [N_y ≤ N_max]
```

**物理意义**：年度发射超量产生环境惩罚，超限过多则不可行。

#### 4.2.4 LCA公式
```
E_LCA = M_tether × 1000 × e_graphene × g_mfg / 1000
```

**物理意义**：电梯建设的"隐含碳" = 材料质量 × 制造能耗 × 碳强度。

#### 4.2.5 EDI计算公式
```
简化EDI：EDI_simple = (E_CO2^{total}/1e6) + (S_max/10)
标准EDI：EDI_std = 1/3[(E_CO2/μ_CO2) + (S_max/μ_Smax) + (E_O3/μ_O3)]
```

**物理意义**：综合环境破坏指标，权衡不同维度的环境影响。

## 第五部分：建模启示与政策建议

### 5.1 核心建模启示

#### 5.1.1 时间尺度不匹配
- **工程时间**：项目工期10-20年
- **环境时间**：黑碳影响持续40+年（τ=4年）
- **启示**：环境评估必须考虑**长期滞后效应**

#### 5.1.2 污染转移现象
- **火箭方案**：运营期高污染（黑碳+CO₂）
- **电梯方案**：建设期高污染（LCA碳债）
- **启示**：存在**代际公平问题**，当代建设 vs 后代运营

#### 5.1.3 尾部风险管理
- **火箭方案**：环境影响的方差极大（箱线图显示）
- **电梯方案**：环境影响可预测性强
- **启示**：风险管理能力是技术选择的关键因素

#### 5.1.4 协同优化可能性
- **发现**：环保（低EDI）与经济（低成本）可同时实现
- **条件**：需要高α（电梯占比）和适当规划
- **启示**：不存在"环保必然昂贵"的固有矛盾

### 5.2 具体政策建议

#### 5.2.1 技术路线建议
1. **优先发展太空电梯**：基于环境与经济双重优势
2. **配套绿电设施**：要求χ≥0.9的清洁能源配套
3. **渐进式建设**：避免一次性大规模LCA碳债

#### 5.2.2 监管框架建议
1. **黑碳实时监测**：建立平流层黑碳监测系统
2. **动态发射管制**：基于S(t)库存的环境熔断机制
3. **年度发射配额**：实施可交易的发射许可证制度

#### 5.2.3 经济激励建议
1. **碳税机制**：对火箭排放征收环境税
2. **LCA补贴**：对电梯建设碳债提供财政支持
3. **绿色债券**：发行专项债券支持清洁太空技术

#### 5.2.4 国际合作建议
1. **全球排放标准**：建立统一的太空活动排放标准
2. **技术共享机制**：促进太空电梯技术的国际转移
3. **联合监测网络**：共建平流层环境监测体系

### 5.3 未来研究方向

#### 5.3.1 模型扩展方向
1. **更细时间尺度**：小时级发射模拟
2. **空间异质性**：考虑发射场地理位置差异
3. **材料创新**：纳入新型低能耗材料参数

#### 5.3.2 数据需求方向
