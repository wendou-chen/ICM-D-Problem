P0-1 题面常量与假设“单一真理源” constants（细改）

动作：新建 /configs/constants.py（或 .yaml），把题面给定参数与自设参数全部集中管理。

题面硬参数必须包含：$M=10^8$ tons、$H=3$、$C_{\text{elev}}=179{,}000$ tons/yr、2050 起、火箭载荷 100–150 tons、10 个发射基地、Q1 perfect conditions、两段运输结构。

自设参数必须做开关/区间：火箭成本、成本衰减率、人均用水、故障率/修复时间（你草稿里已写了“每 5 年降 10%”“175L”等，必须参数化）。

思路草稿

验收标准：全仓库任何脚本不得出现“魔法数字”；所有参数必须可追溯 source=problem/assumption/literature。

P0-2 场景定义与基线闭式计算（细改）

动作：写 scripts/baseline_calc.py（或 notebook），输出 Scenario A/B/C 的基线工期与成本表达式（先不做仿真）。

关键点：Scenario A（“纯电梯”）仍需考虑 Apex→Moon 的火箭段（题面明确两段）。

验收标准：能一键输出

$T_A=\frac{M}{H\cdot C_{\text{elev}}}$（并显式说明单位）

Scenario B：基于你设定的年发射能力参数算最小工期

Scenario C：给出可画 Pareto 的参数扫描（哪怕先用固定比例也行，但要为后续“时变策略”留接口）。

P0-3 工程归档：D 题“数据爬虫/网络算法”下线（粗改）

动作：把 crawler、网页清洗、数据抓取依赖移动到 /legacy_d/ 并从主入口隔离（避免 import 污染）。

保留可复用层：实验管理（runner/logging）、绘图模板、sensitivity 框架（这些是跨题型资产）。

验收标准：pip install -r requirements.txt && python main.py 不依赖任何爬虫包/外网。

P0-4 统一单位体系与数据结构规范（细改）

动作：定义全局单位约束：质量统一用 metric tons（或 kg，但必须全仓一致）、时间统一用 year 或 month（推荐 baseline 用 year，仿真用 month）。

验收标准：任何函数签名都要写清楚 tons/month 或 tons/year；输出结果 DataFrame 字段命名统一（如 t_month, cum_mass_tons, cost_usd）。

动作：main.py 支持 CLI 参数：--scenario A/B/C --seed --export_dir --config；结果落盘到 /outputs/（csv+fig）。
