## 一、融合优点后的 Q1 **最终整合方案**（更稳、写作+工程一致）

### 总原则（写在 Q1 章节开头）

* **基线（Baseline）**：完全按题面 single-step，取 (k=1)。
* **敏感性（Reality check）**：引入架构倍率 (k\in{4,8,16}) 作为“等效任务单位（SMU）”的复杂度，检验结论是否稳健。
* **成本**：全部用区间（low/med/high）画“带状 Pareto”，避免押单点。

## 二、关键建模修正：(\beta) 必须“有物理含义”，不要随便猜

### 推荐的 (\beta) 写法（审稿友好）

把火箭单次成本分解为：
[
C_L = C_{\text{fixed}} + C_{\text{prop}}
]

* (C_{\text{fixed}})：折旧、地面支持、运维、航电、保险等“与燃料无关”的固定部分
* (C_{\text{prop}})：推进剂与与能量需求强相关的部分

Apex→Moon 的单次成本写成：
[
C_A = C_{\text{fixed,A}} + \gamma\cdot C_{\text{prop}}
]
其中 (\gamma\in(0,1)) 是“燃料相关成本折扣”，可用“Δv 更小”来解释；而固定项 (C_{\text{fixed,A}}) 不会随着 fuel 减少等比例下降。

为了保持 Q1 简洁，你可以进一步定义“每吨成本折扣”：
[
c_A = \beta\cdot c_R,\quad \beta\in[\beta_{\min},\beta_{\max}]
]
但要在论文里说明：

> (\beta) 并不是纯燃料比，而是**综合折扣**，我们用区间覆盖“燃料显著降低但固定成本仍在”的不确定性。

**建议区间（不写死，作为默认起点）**：(\beta\in[0.2,0.8]) —— 比 0.1–0.2 更不容易被质疑（因为固定成本可能占比很高）。区间宽一些反而更稳。

## 三、(k)（加油/多次支撑）怎么写才“不违题、还不被打穿”

### 写作话术（关键）

* 题面定义了“单次任务可交付 100–150 tons 到月球”，我们把它称为**标准任务单位 SMU**，基线下 SMU 对应一次发射（(k=1)）。
* 现实中一个 SMU 可能需要多次支撑发射（轨道加油/补给），我们用倍率 (k) 表示“每个 SMU 需要的等效发射次数”，在敏感性分析中取 (k>1)。

### 数学上最稳的等效化（同时影响吞吐与成本）

[
q_{\text{eff}}=\frac{q}{k},\quad
C_{R,\text{eff}}=\frac{365Krq}{k},\quad
c_{R,\text{eff}}=k\cdot \frac{C_L}{q}
]
这会自然导致：(k) 越大，“更慢更贵”，且不会改变你 Q1 曲线结构（只是在敏感性层画不同 (k) 的曲线）。

### 工程隔离要求（避免答非所问）

* **baseline 模块**固定传入 (k=1)
* **sensitivity 模块**才允许传入 (k>1)
* 通过 `assert` 或配置开关防止混用（例如：`if mode=="baseline": assert k==1`）

## 四、最终输出物（两张图 + 一段敏感性），与原先叙事完全一致

### 图 1：工期 vs (\alpha)（吞吐极限）

[
T_C(\alpha)=\max\left(\frac{\alpha M}{C_E},\frac{(1-\alpha)M}{C_R}\right),\quad
T_{\min}=\frac{M}{C_E+C_R}
]
叙事：只有混合才能逼近下界 (T_{\min})，因此必须考虑 Scenario C。

### 图 2：成本–工期带状 Pareto（真正 trade-off）

[
\text{Cost}_C(\alpha)=\alpha M,(c_E+c_A) + (1-\alpha)M,c_R
]
用成本区间（low/high）给出“带状曲线”，叙事：更短工期通常意味着更高成本，存在拐点（但不要先验宣称形状，一定要由参数扫描得出）。

### 敏感性（可选但强烈建议）：叠加 (k>1) 的“现实复杂度曲线”

* baseline：只画 (k=1)
* sensitivity：叠加 (k=4,8,16) 的曲线（虚线/淡色），一眼展示“现实会把方案推向更慢更贵”，从而增强“电梯/混合”的战略意义。

## 五、工程修改的最小改动清单

1. `constants.py`

* 把所有成本都改为 **区间 + 单位明确**（USD/launch、USD/ton）
* 增加 `BETA_RANGE`（建议宽一些，如 0.2–0.8）
* 增加 `K_SET = (1,)` 用于 baseline；`K_SENS_SET=(1,4,8,16)` 用于 sensitivity（或分开字段名避免混淆）

2. `capacity.py`

* 不要直接把 (k) 写死在全局计算中；改为函数参数 `k_arch: int = 1`
* baseline 调用统一传 `k_arch=1`

3. `tradeoff_q1.py`

* 外层循环：成本情景（low/high）与（可选）(k) 情景
* 内层循环：(\alpha) 扫描
* 输出两张图：

  * time vs alpha（baseline 必出）
  * cost vs time（baseline 必出，band 必出；(k>1) 作为 sensitivity 叠加）

## 结论（现在应采取的决策）

* **必须做第二张“成本–工期曲线”**，但要用**区间带**而不是单点真值。
* **(k) 不进入基线**，只进敏感性；且必须同时作用于吞吐与成本（Gemini 的方向对，但需要更严格的隔离与解释）。
* **(\beta) 必须通过“固定成本 + 燃料相关成本”的分解来解释**，用宽区间覆盖不确定性，避免被质疑。
