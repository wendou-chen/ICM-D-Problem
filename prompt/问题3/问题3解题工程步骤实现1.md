## Step1（闭式需求层：水需求序列 + 物理可行性爆点）

### 1.1 变量名（工程）

* `P`：population
* `w`：water_L_per_person_day
* `eta`：recycle_efficiency
* `d_day_ton`：net_daily_demand_ton
* `D_year_ton`：annual_demand_ton
* `C_E_year`：elevator_capacity_year (tons/year)
* `C_E_day`：`C_E_year/365`

### 1.2 公式（论文可粘贴）

净补给需求（吨/天）：
[
d_{\text{day}}=\frac{P\cdot \bar w\cdot(1-\eta)}{1000}
]
一年净需水量：
[
D_{\text{year}}=365,d_{\text{day}}
]
电梯日均供给能力：
[
c_{E,\text{day}}=\frac{C_E}{365}
]

**物理可行性判据（爆点）**：
[
d_{\text{day}} > \frac{C_E}{365}\ \Rightarrow\ \text{仅靠电梯无法持续供水}
]
（如果你取 $C_E=3\times179,000$，则 $C_E/365\approx1471$ 吨/天。）

* 表：`required_lifts = D_year_ton / 179000`（等效电梯数量）

## Step2（交付模型接口层：把 Q1/Q2 运力“投影”到水）

### 2.1 变量名（工程）

* `C_R_year = 365*K*r*q`：rocket_capacity_year
* `a_E, a_B, s_R`：availability/success factors
* `phi_E, phi_R`：capacity shares for water
* `cE_day_w, cR_day_w`：daily water capacity by mode

### 2.2 公式（继承 Q2）

有效年运力：
[
\tilde C_E=a_E C_E,\qquad
\tilde C_R=a_B s_R\cdot C_R,\quad C_R=365Krq
]
给水占比后：
[
\tilde C_E^{(w)}=\phi_E\tilde C_E,\qquad
\tilde C_R^{(w)}=\phi_R\tilde C_R
]
日上限：
[
c_{E,\text{day}}^{(w)}=\frac{\tilde C_E^{(w)}}{365},\qquad
c_{R,\text{day}}^{(w)}=\frac{\tilde C_R^{(w)}}{365}
]

### 2.3 工程检查点（必须写成 `assert`）

* `cE_day_w + cR_day_w >= d_day_ton` 是否成立

  * 不成立 ⇒ “即便全力运水也会断供”，直接输出不可行标记（用于论文结论）

## Step3（库存可行性层：确保一年不断供）

### 3.1 状态变量与决策变量（工程命名）

* `W[t]`：`water_stock_ton[t]`（库存）
* `xE[t]`：`ship_elevator_ton[t]`（电梯运水量）
* `xR[t]`：`ship_rocket_ton[t]`（火箭运水量）
* `W0`：`initial_stock_ton`

### 3.2 库存动力学（核心公式）

以天为步长 $t=0,\dots,364$：
[
W_{t+1}=W_t+x_{E,t}+x_{R,t}-d_{\text{day}}
]
约束：
[
0\le x_{E,t}\le c_{E,\text{day}}^{(w)},\quad
0\le x_{R,t}\le c_{R,\text{day}}^{(w)},\quad
W_t\ge0
]

### 3.3 策略实现（两种都要，论文能对比）

#### Policy A：`order_up_to (s,S)`（推荐主策略）

* 安全库存：$s=L\cdot d_{\text{day}}$
* 目标库存：$S=(L+B)\cdot d_{\text{day}}$
* 当天总补给量：
  [
  x_t=\min{c_{E,\text{day}}^{(w)}+c_{R,\text{day}}^{(w)},\ \max(0,S-W_t)}
  ]
  再做通道拆分（先便宜后昂贵）：
  [
  x_{E,t}=\min(x_t,c_{E,\text{day}}^{(w)}),\quad
  x_{R,t}=x_t-x_{E,t}
  ]

#### Policy B：`rate_matching + buffer`（作为稳态对照）

* 平时：$x_t=d_{\text{day}}$（若容量允许）
* 当 $W_t<s$：触发 surge（短期提高 `phi_R` 或 `r`）

### 3.4 工程输出

* 图 3：`inventory_W_t_curve`（$W_t$ 曲线，必须显示是否触底）
* 图 4：`daily_shipments_xE_xR`（$xE_t, xR_t$ 时间序列）
* 指标：`stockout_flag = any(W_t < 0)`（是否断供）

## Step4（额外成本与时间线：ΔCost 与 ΔTimeline 的定义与计算）

### 4.1 成本口径（必须对齐 Q1）

#### 火箭运水成本（传统火箭）

当天火箭发射次数：
[
N_{R,t}=\left\lceil \frac{x_{R,t}}{q}\right\rceil
]
成本：
[
\Delta C_R=\sum_t N_{R,t}\cdot C_L
]
如考虑失败率（期望重发）：
[
\mathbb E[\Delta C_R]\approx \sum_t \left\lceil \frac{x_{R,t}}{q}\right\rceil\frac{C_L}{s_R}
]

#### 电梯体系运水成本（必须包含 Apex→Moon 段）

电梯段（Earth→Apex）单位吨成本：$c_E$；
Apex→Moon 段按发射次数：
[
N_{A,t}=\left\lceil\frac{x_{E,t}}{q_A}\right\rceil,\qquad
\Delta C_E=\sum_t \left(x_{E,t}\cdot c_E + N_{A,t}\cdot C_A\right)
]
（这点是题面“两段式”硬约束。）

总额外成本：
[
\Delta C=\Delta C_E+\Delta C_R
]

### 4.2 时间线（两种定义，主解+扩展）

**主解（运营期一年保障的 timeline）**

* 输出 “每日补给计划” + “最低初始库存 $W_0$ / 安全库存天数 $L$”
* 若容量不足导致无法维持：输出不可行天数/首次断供时间

**扩展（挤出效应，建设期预囤水）**

* 在建设期把部分运力分给水，导致建材完工时间变长：
  [
  \Delta T_{\text{crowd-out}} = T_{\text{build+water}} - T_{\text{build-only}}
  ]
  （单独脚本做，不污染 Q3 主循环）

### 4.3 工程输出

* 表：`q3_summary_table.csv`

  * 列：`eta, phi_E, phi_R, policy, W0_days, feasible, DeltaCost, stockout_day(if any)`
* 图 5：`cost_breakdown_bar`（$\Delta C_E$ vs $\Delta C_R$）

## Step5

### 5.1 输出指标（论文很加分）

* 断供概率：$\Pr(\min_t W_t<0)$
* 95% 服务水平：$\Pr(\min_t W_t\ge0)\ge0.95$
* 风险指标：$\mathrm{VaR}*{0.95}(W*{\min})$

### 5.2 工程要点（避免 Q2 的坑）

* 电梯停机必须是 **连续 down days（burst）**，不是每天乘折扣
* 火箭失败要么只做“payload loss”，要么再加 `tau_reset_days`，但模型与代码必须一致

# 最终：Q3 的最小可运行（MVP）启动顺序

1. **先做 Step1**：需求数量级 + 两张爆点图
