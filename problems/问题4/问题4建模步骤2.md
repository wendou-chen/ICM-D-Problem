## 0) 先判定：为什么“对应不上”（也是现在缺两张图的根因）

现在的 `run_q4_sweep` 有两个结构性限制：

1. **工期维度被写死**：`duration_days=365*5` 固定跑 5 年，导致 `T_years` 不随策略变化。
   → 这会让“Time–EDI Pareto”在当前工程里 **画不出有意义的权衡**（所有点横坐标都一样）。

2. **没有 Monte Carlo 批量样本**：每个 `(alpha, chi)` 只跑一次随机仿真。
   → 这会让“Tail Risk（VaR/CVaR/箱线图）”在当前工程里 **无法成立**（没有分布就谈不上尾部风险）。

结论：

* **要补两张图**不是“画图脚本缺”，而是 **数据结构缺**：缺 `T_years` 的“可变定义”与缺 Monte Carlo 样本集。

# A) 数据层：把“时间”变成可优化变量（否则画不出 Time–EDI）

### A1. 把 Q4 的 `T_years` 定义为“完成目标任务所需时间”

现在用的是“水库存保供仿真”，固定 5 年。要有策略相关的时间，有两种路径：

**路径 A（推荐，最符合题意）**：改用/接入 Q1 的“建材运输达到 $M=10^8$ 吨”的完成时间。

* 每天累计交付建材：`cum_mass += x_E + x_R_success`
* 结束条件：`cum_mass >= M_total`
* 工期：`T_years = t_stop / 365`

**路径 B（不推荐但能救急）**：在现有水模型上定义“达到某服务水平所需稳定期”等 proxy time。

* 论文说服力明显弱（容易被问：这和建月球城的工期有什么关系？）

✅ 现在要补 Time–EDI，基本意味着必须走 **路径 A**。

### A2. 需要在 daily_logs 里补两个字段

当前日志只用到：`attempts_R` 和 `x_E`。
为了计算完成时间，至少还要：

* `x_R`：火箭**当日实际交付吨数**（不是尝试次数）
* `cum_mass`（可选）：累计交付（也可以后处理算）

因此建议在 `simulate_inventory_trajectory(..., return_daily_logs=True)` 里，把每天 log 扩成：

```python

  "attempts_by_site": {...}
}
```

### B2. 为 Tail Risk 增加 “Monte Carlo 采样表”

目前每个点只跑 1 次：
要画 tail risk，你需要每个策略点跑 `N_MC` 次（例如 30），输出 reminder：

* 单次输出：`S_max_ton`, `EDI_proxy`（或真实 EDI）
* 统计：
  [
  \mathrm{VaR}*{0.95}(S*{\max}),\quad \mathrm{CVaR}*{0.95}(S*{\max})
  ]
  工程上建议输出两张表：

1. `summary_q4_sweep.csv`：每个点汇总统计（mean/VaR/CVaR）

```python
for mc in range(N_MC):

    sim_res = simulate_inventory_trajectory(...)
    ledger = EnvLedger(...)
    ...
    env = ledger.finalize()
    samples.append({alpha, chi, mc, env["S_max_ton"], env["E_CO2_ton"], EDI})
# 然后对 samples 分组算 VaR/CVaR 写入 summary
```
