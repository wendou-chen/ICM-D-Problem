# Step5（Monte Carlo 风险评估）工程执行步骤与要点

## Step5-0（参数冻结：Risk Preset 入库 + severe 校准目标）

### 0.1 必须入库的配置变量（建议：`configs/risk_params.yaml`）

**Simulation Settings**

* `n_sims`：模拟次数 $N$（建议 1000）
* `seed`：随机种子（如 42）
* `horizon_days`：仿真天数（365）
* `n_spaghetti`：面条图抽样路径数（50–100）

**Demand / Inventory**

* `P`：人口（100000）
* `w_L_per_person_day`：人均日用水（L/人/天）
* `eta_recycle`：回收率 $\eta$（如 0.98）
* `L_safe_days`：安全库存天数 $L$（基线 15；后续扫描）
* `B_buffer_days`：缓冲天数 $B$（若使用 order-up-to）

**Capacity & Cost（继承 Step4 / Q1-Q2）**

* `C_E_year`：电梯总年运力（吨/年）
* `K_sites`：火箭基地数 $K$
* `r_launches_per_site_per_day`：单基地日发射频次 $r$
* `q_ton_per_launch`：单次有效载荷 $q$（吨）
* `phi_E` / `phi_R`：给水运力占比
* `C_L`：单次发射成本
* `c_E_per_ton`：电梯单位吨成本（Earth→Apex）
* `q_A_ton`、`C_A`：Apex→Moon 转运段（火箭）载荷与成本（若你 Step4 已实现两段式，这里沿用）

**Risk Parameters（核心：随机性）**

* `p_R_fail_per_launch`：火箭单次发射失败率 $p_R$，成功率 $s_R=1-p_R$
* 电梯 burst 故障（二选一，只能选一种叙事以保持一致性）
  **Option A（推荐）离散 burst 模型：**

  * `p_E_fail_daily`：电梯每日触发停机概率
  * `repair_days_min` / `repair_days_max`：停机持续天数分布（均匀/离散均可）
    **Option B CTMC 模型：**
  * `lambda_E_per_day`、`mu_E_per_day`（故障/修复速率）

### 0.2 severe 校准目标（必须写进日志/输出）

你的 Step4 severe 里有一个“长期可用率”目标（例如 $a_E=0.75$）。
Step5 的随机模型必须满足：
[
\mathbb{E}[\hat a_E] \approx a_E^{\text{target}}=0.75
]
其中
[
\hat a_E=\frac{\text{up_days}}{365}
]

**若用离散 burst（Option A）**，近似校准关系：
[
a_E \approx \frac{1}{1+p_{E,\text{fail}}\cdot \mathbb{E}[D]}
]
其中 $D$ 为 repair days 随机变量（如 $U[D_{\min},D_{\max}]$ 则 $\mathbb{E}[D]=\frac{D_{\min}+D_{\max}}{2}$）。

> **验收点**：跑完 MC 后打印 `mean_availability`，若偏离 0.75 超过 ±0.03，参数不合格。

## Step5-1（闭式需求锁定：把“每日净需求”固定为常数输入）

### 1.1 工程变量名

* `d_day_ton`：`net_daily_demand_ton`

### 1.2 公式（与 Step1 保持一致）

净外部补给需求（吨/天）：
[
d_{\text{day}}=\frac{P\cdot \bar w\cdot (1-\eta)}{1000}
]
一年需求：
[
D_{\text{year}}=365\cdot d_{\text{day}}
]

**验收点**：把 `D_year_ton` 与 Step4 年运输总量对比，数量级必须一致（你当前 severe、98% 下已接近 348 吨/天 → 年约 127k 吨）。

## Step5-2（随机运力生成器：Elevator burst + Rocket binomial）

这一部分是 Step5 的“引擎”，必须把“计划运量”转为“实际到货运量”。

### 2.1 电梯 burst 状态机（连续停机，不允许每日折扣）

**工程变量名**

* `elev_down_remain`：剩余停机天数（int）
* `cE_day_w_nominal`：水可用的电梯日上限（不含故障）
* `xE_plan_ton` / `xE_actual_ton`

**运力上限（继承 Step2）**
[
c_{E,\text{day}}^{(w)}=\frac{\phi_E\cdot C_E}{365}
]
（如果你在风险层仍保留 $a_E$ 的“期望”项，这里不要再乘一次；burst 状态机本身就会产生可用率。）

**状态转移逻辑（离散 burst）**

* 若 `elev_down_remain > 0`：
  [
  x_{E,t}^{\text{actual}}=0,\quad \text{and } elev_down_remain \leftarrow elev_down_remain-1
  ]
* 否则（电梯 up）：以概率 $p_{E,\text{fail}}$ 触发停机：
  [
  \Pr(\text{fail at day }t)=p_{E,\text{fail}}
  ]
  若触发，抽样 $D_t$（repair days），并令当日停运：
  [
  elev_down_remain \leftarrow D_t,\quad x_{E,t}^{\text{actual}}=0
  ]
  若未触发：
  [
  x_{E,t}^{\text{actual}}=x_{E,t}^{\text{plan}}\le c_{E,\text{day}}^{(w)}
  ]

**校准输出**：每条路径记录 `up_days`，最终用于 $\hat a_E$。

---

### 2.2 火箭失败（必须按“多次发射 Binomial”，禁止“当天全灭”）

**工程变量名**

* `xR_plan_ton` / `xR_actual_ton`
* `n_plan`：当天计划发射次数
* `n_succ`：当天成功次数
* `p_R_fail_per_launch`，`s_R = 1 - p_R_fail_per_launch`

**火箭名义日上限（继承 Step2）**
[
c_{R,\text{day}}^{(w)} = \phi_R \cdot (K\cdot r\cdot q)
]
因为 $C_R=365Krq$，所以日能力就是 $Krq$（吨/天）。

**发射统计**
[
n_t^{\text{plan}}=\left\lceil \frac{x_{R,t}^{\text{plan}}}{q}\right\rceil
]
[
n_t^{\text{succ}}\sim \mathrm{Binomial}\left(n_t^{\text{plan}},\ s_R\right)
]
[
x_{R,t}^{\text{actual}}=n_t^{\text{succ}}\cdot q
]

## Step5-3（单次年度模拟：库存更新 + 断供事件）

### 3.1 工程变量名（核心状态）

* `W_ton[t]`：库存序列（长度 366）
* `W0_ton`：初始库存（由安全库存决定）
* `xE_plan_ton[t], xR_plan_ton[t]`：计划
* `xE_actual_ton[t], xR_actual_ton[t]`：实际
* `stockout_flag`：是否断供（bool）
* `stockout_day`：首次断供日（int or None）

### 3.2 初始库存（安全库存）

[
W_0 = L\cdot d_{\text{day}}
]
其中 $L=$ `L_safe_days`。

### 3.3 库存动力学（用“实际到货”更新）

以天为步长：
[
W_{t+1}=W_t + x_{E,t}^{\text{actual}} + x_{R,t}^{\text{actual}} - d_{\text{day}}
]
断供事件定义（主指标基于事件，而不是“天数比例”）：
[
\text{stockout occurs if }\min_{t\in[0,365]} W_t<0
]

### 3.4 计划补给策略（复用 Step3，不要在 Step5 改策略）

**推荐仍用 order-up-to（s,S）**
[
s=L\cdot d_{\text{day}},\quad S=(L+B)\cdot d_{\text{day}}
]
[
x_t^{\text{plan}}=\min{c_{E,\text{day}}^{(w)}+c_{R,\text{day}}^{(w)},\ \max(0,S-W_t)}
]
通道拆分（先电梯后火箭）：
[
x_{E,t}^{\text{plan}}=\min(x_t^{\text{plan}},c_{E,\text{day}}^{(w)}),\quad
x_{R,t}^{\text{plan}}=x_t^{\text{plan}}-x_{E,t}^{\text{plan}}
]

## Step5-4（成本核算：按“尝试次数付费”+ 组件拆分用于 Pareto）

### 4.1 工程变量名

* `cost_total_usd`
* `cost_components`（dict）：用于 Pareto 的分项成本
  建议键：`Elevator_OPEX`, `ApexMoon_Transfer`, `Rocket_Base`, `Rocket_Failure_Waste`（可选 `Emergency_Surge`）

### 4.2 成本公式（与 Step4 口径一致）

**火箭成本（按尝试次数付费）**
[
C_{R,t}=n_t^{\text{plan}}\cdot C_L
]
如果要显式“失败浪费”分项：
[
C_{R,t}^{\text{waste}}=(n_t^{\text{plan}}-n_t^{\text{succ}})\cdot C_L
]
[
C_{R,t}^{\text{base}}=n_t^{\text{succ}}\cdot C_L
]
（两者相加回到总成本，便于做 Pareto。）

**电梯两段式成本（若你 Step4 已实现两段式）**

* Earth→Apex：
  [
  C_{E,t}^{\text{opex}}=x_{E,t}^{\text{actual}}\cdot c_E
  ]
* Apex→Moon 转运（按转运火箭次数）：
  [
  n_{A,t}=\left\lceil\frac{x_{E,t}^{\text{actual}}}{q_A}\right\rceil,\quad
  C_{A,t}=n_{A,t}\cdot C_A
  ]
  总成本：
  [
  C_{\text{total}}=\sum_{t=1}^{365}\left(C_{R,t}+C_{E,t}^{\text{opex}}+C_{A,t}\right)
  ]

**验收点**：Step5 的 `mean(cost_total)` 应接近 Step4（允许略高，因为失败浪费会把尾部抬起）。

## Step5-5（Monte Carlo 汇总指标：断供概率 + VaR + 可用率校准）

### 5.1 工程变量名（样本集合）

* `stockout_flags[i]`
* `Wmin_samples[i]`（每次模拟的 $\min_t W_t$）
* `cost_samples[i]`
* `availability_samples[i]`（每次模拟的 $\hat a_E$）

### 5.2 指标公式

断供概率：
[
P_{\text{stockout}}=\frac{1}{N}\sum_{i=1}^N \mathbf{1}{\min_t W_t^{(i)}<0}
]
成本 95% VaR：
[
\mathrm{VaR}*{0.95}(C)=\text{Quantile}*{0.95}\left({C^{(i)}}\right)
]
库存尾部风险（危险取低分位）：
[
\mathrm{VaR}*{0.05}(W*{\min})=\text{Quantile}*{0.05}\left({\min_t W_t^{(i)}}\right)
]
可用率校准检查：
[
\overline{\hat a_E}=\frac{1}{N}\sum*{i=1}^N \hat a_E^{(i)}\approx 0.75
]

## Step5-7（图表输出：Spaghetti + Pareto + Histogram）

### 7.1 面条图（库存风险）

* 左 y：柱（各组件平均成本）
* 右 y：累计占比折线
  标注 80% 截点对应的“前 k 项”。

### 7.3 成本直方图（Budget-at-Risk）

* 竖线：mean + VaR95

# Step5 最终验收清单（跑完一眼确认正确）

1. `mean_availability ≈ 0.75`（severe 校准成立）
2. 火箭失败使用 Binomial（你能从日志看到 `n_plan, n_succ`）
3. 主指标是 `P_stockout`（一年内是否断供）
4. Pareto 图组件 ≥4，能指出“vital few”
5. Step5 均值成本接近 Step4，且 VaR95 明显高于均值（风险尾部存在）
